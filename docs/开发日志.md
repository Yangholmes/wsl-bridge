32. 修复 Topology 探测中 WSL IP 丢失与 Hyper-V 漏检问题：
    - 根因定位：`wsl.exe --list --quiet` 在当前环境输出 UTF-16LE（包含 `\0`），原逻辑按 UTF-8 解码导致 distro 名被污染，`wsl.exe -d <distro>` 解析失败，IP 全为空。
    - 新增通用命令输出解码：自动识别 UTF-16LE/BE（BOM 与零字节特征）并回退 UTF-8，统一清理 BOM 与 NUL。
    - WSL IP 解析增加回退链路：优先 `hostname -I`，失败时回退 `ip -4 -o addr ...`。
    - Hyper-V 扫描增强：
      - 优先返回运行态 VM（无运行态时回退全部 VM）。
      - PowerShell 执行增加 `powershell.exe/powershell/pwsh.exe/pwsh` 候选回退。
      - 当 `Get-VM` 路径无结果时，回退 `Get-CimInstance root\\virtualization\\v2` 探测运行中的 VM 名称。
    - 补充单元测试：UTF-16 解码、BOM/NUL 清理、IP 选取优先级。
33. 增强 Hyper-V 漏检回退链路（第二轮）：
    - `run_powershell` 增加绝对路径候选：`%SystemRoot%\\System32\\WindowsPowerShell\\v1.0\\powershell.exe` 与 `Sysnative`，降低 GUI 进程 PATH/位宽差异影响。
    - 当 `Get-VM + Get-VMNetworkAdapter` 无结果时，新增 `Get-VM` 仅名称回退（`Name||`），确保至少能识别 VM 实例。
    - CIM 回退脚本去除 `Caption='Virtual Machine'` 约束，仅按 `EnabledState=2 + ElementName` 过滤，兼容不同系统语言/字段表现。
34. 重构 Hyper-V 拓扑实现（修正"读取到 Server 而非 VM 列表"问题）：
    - 移除 Hyper-V 文本拼接与 CIM 猜测回退路径，改为 `Get-VM` + `Get-VMNetworkAdapter` 生成结构化对象。
    - PowerShell 端统一输出 JSON（`ConvertTo-Json`），Rust 端用 `serde_json` 反序列化，避免行文本解析歧义。
    - 数据语义收敛到"Hyper-V 虚拟机实例"：`vm_name / v_switch / ip`；并按 VM 名排序返回。
    - 保留名称级回退：当网卡信息读取失败时仍可返回 VM 列表（`ip/v_switch` 为空）。
    - 新增 `parse_hyperv_json` 单测（单对象/数组两种 JSON 形态）。
35. UI 卡顿与 Hyper-V 调试可观测性改进：

    - 新增 `debug_hyperv_probe` 命令，返回 Hyper-V 探测步骤的原始 stdout/stderr、执行器路径、状态码、解析出的 VM 名称。

      - 根因是 Proxy 在转发纯 HTTP upstream 请求后，立即对上游 socket 执行 `shutdown(Write)`
      - 该“半关闭写端”行为会被部分 Node HTTP 服务解释为客户端提前断开，导致服务端直接关闭响应，浏览器侧表现为 `ERR_EMPTY_RESPONSE`
    - 修复方案：
      - 移除 HTTP listener / HTTPS listener 下纯 HTTP upstream 分支中的 `shutdown(Write)`
      - 改为在请求写入完成后执行 `flush()`，避免过早半关闭上游连接
    - 回归测试：
      - 新增回归测试，模拟“若代理提前 half-close 则服务端拒绝返回响应”的上游行为
      - 验证当前 Proxy 不会在收到响应前半关闭纯 HTTP upstream
    - 验证：
      - `cargo fmt --manifest-path src-tauri/crates/core/Cargo.toml`
      - `cargo test --manifest-path src-tauri/crates/core/Cargo.toml proxy_http_listener_does_not_half_close_plain_http_upstream_before_response`
      - `cargo test --manifest-path src-tauri/crates/core/Cargo.toml`

239. Proxy 其他协议同类半关闭问题审计：
    - 审计范围：
      - HTTP listener -> HTTP / HTTPS / WS / WSS / gRPC upstream
      - HTTPS listener -> HTTP / HTTPS / WS / WSS / gRPCS upstream
      - Legacy `http_proxy` / `socks5_proxy` / `tcp_fwd` 转发链路
    - 结论：
      - 同类风险仅存在于“纯 HTTP upstream 请求发完后立即 half-close”的两条分支：
        - `HTTP listener -> HTTP upstream`
        - `HTTPS listener(TLS 终止) -> HTTP upstream`
      - HTTPS / WSS / gRPCS 分支当前使用的是 TLS close notify / 隧道 relay，未发现与本次 `ERR_EMPTY_RESPONSE` 同源的问题
      - Legacy `http_proxy` / `socks5_proxy` / `tcp_fwd` 当前也未发现同类过早半关闭问题
